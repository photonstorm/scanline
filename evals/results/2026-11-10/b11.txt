CAUSE: drawSparks, called every frame, compiles and links a brand-new shader program for the glowing sparks (additive-blend draws) and deletes it again at the end of the frame, instead of creating it once and reusing it. Shader compile and link is expensive, and doing it every frame causes the stutter.

EVIDENCE:
- In cap_10 the draw_list shows draws 10-21 (the 12 sparks, blend SRC_ALPHA/ONE) using prg_146. All other draws use prg_1.
- A program handle as high as 146 at frame 144 means a new program is created roughly every frame.
- resource prg_146 says: "Created in frame 144, DESTROYED in frame 145, last used in frame 144", created at link (scene.js:28) < drawSparks (scene.js:317) < frame (scene.js:389). It also shows shd_291 and shd_292 for it, so two new shaders per frame as well. The program lives for exactly one frame.
- Its listing said "LINK FAILED", which is odd, but the draws still rendered correctly (draw 10 changed 199 pixels), so this looks like a quirk of reading a destroyed program rather than a real failure.
- The spark draws are the same quad geometry on the same texture, so one shared program would work.

FIX: Build the spark program once (at init, or lazily and cached) and reuse it every frame. Remove the per-frame createProgram, compile, link and deleteProgram calls from drawSparks. Ideally share the existing program, or make the spark shader static.
